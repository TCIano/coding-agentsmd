# 项目协作规则

开始任务前，先读 `README.md`、`CONTEXT.md`、`docs/index.md` 和本次工作相关的现行文档。

## 每次任务

1. 建立项目内任务编号；如有外部 issue，记录链接。
2. 功能、数据、安全或性能缺陷要建立 `docs/bugs/` 记录。纯文案或排版修正可只写任务变更记录。
3. 从 `docs/_templates/` 新建正式文档，填写状态、负责人和关联任务。起始草稿及临时材料不是现行事实。
4. 结束任务前写 `docs/tasks/` 中的任务变更记录：改了什么、为什么、如何验证、哪些文档已更新、哪些检查后无需更新及原因。
5. 中断或交接时更新工作接续快照；发布或发生重要功能、架构、外部接口变化时保存项目状态快照。
6. 遇到文档与代码、测试或设计决定冲突，标为“待核实”，记录位置、时间和负责人。与本次修改相关的冲突须在合并前解决。

快照和示例只记录必要的非敏感信息；不要写入凭据、密钥或个人数据的具体值。

验证未运行时记录原因和影响。项目维护者可以在记录风险和后续验证任务后决定是否合并。合并负责人确认文档影响判断；发布时审阅汇集的 `docs/CHANGELOG.md`。

项目当前事实以现行文档及其验证证据为依据。不同来源冲突时不要自行猜测哪一边正确。
